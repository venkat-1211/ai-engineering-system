# Knowledge Model and Classification

## Categories
Project facts; user requirements; decisions; procedures; lessons; standards; hypotheses; recommendations; historical records.

## Scope
`task`, `project`, `organization-shared`, `general`. Use the narrowest scope that works. Project knowledge is not shareable by default.

## Trust labels
- `Verified`: checked against authoritative source or reproducible evidence.
- `Approved`: explicitly approved by designated human authority.
- `User-provided`: stated by user, not independently verified unless separately checked.
- `Observed`: directly seen in current environment.
- `Inferred`: reasoned from evidence and explicitly identified as inference.
- `Proposed`: recommendation awaiting review/decision.
- `Unverified`: not yet checked.
- `Superseded`: replaced by a newer applicable record.

Approval is governance status; verification is evidence status. Do not conflate them.

## Minimum metadata
Stable ID, title, category, scope, project/component, summary, status/trust, sources, recorder, owner, dates, applicable version, review trigger, sensitivity, related records.

Classify conservatively. Keep secrets and unnecessary personal data out. Label claims separately when their trust levels differ.
