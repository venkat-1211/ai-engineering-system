# Knowledge Provenance and Evidence

Material claims must be traceable. Use stable repository paths/symbols, commit hashes, issue/PR IDs, test names and run IDs, deployment records, decision IDs, or approved references. Include version/date where needed.

Distinguish current-source inspection, executed test output, user-provided requirement, approved decision, live observation, inference, and recommendation. Record environment and scope for test evidence; local success does not prove production behavior.

Never invent citations, output, approvals, owners, timestamps, or reproducibility. Record unavailable evidence as a limitation. For high-impact claims capture claim, source, observed date, applicable version, verification method/result, trust label, and limitation.

Do not copy secrets or unnecessary personal data into evidence records; redact safely.
