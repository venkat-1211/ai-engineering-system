# Orchestration Readiness Checklist

Use before assigning multiple agents. Mark each item `Yes`, `No`, or `Not applicable` and explain any `No`.

- [ ] Multi-agent work provides clear value over a single agent.
- [ ] User outcome and acceptance criteria are clear.
- [ ] Repository and branch have been identified.
- [ ] Applicable root instructions and Stages 1–4 standards are known.
- [ ] Actual technology/platform versions will be inspected, not assumed.
- [ ] One orchestrator is accountable for coordination.
- [ ] Every task has exactly one accountable owner.
- [ ] Task boundaries and acceptance criteria are testable.
- [ ] Dependencies and shared interfaces are identified.
- [ ] File read/write ownership is explicit.
- [ ] Parallel tasks do not have unresolved write conflicts.
- [ ] Permissions and prohibited actions are explicit.
- [ ] Human approval points are identified.
- [ ] Independent review and verification are planned.
- [ ] Handoff and evidence format is agreed.
- [ ] Failure and escalation path is known.

If a critical item is `No`, do not start parallel execution until resolved.
