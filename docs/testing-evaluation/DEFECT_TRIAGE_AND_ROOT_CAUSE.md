# Defect Triage and Root Cause Analysis

## Triage
Capture reproducible steps, expected/actual behavior, affected versions, environment, severity rationale, frequency, scope, and available evidence. Avoid assigning severity based only on emotional impact or ticket age.

## Prioritization
Consider user impact, security/privacy, data integrity, availability, workaround, exposure, and likelihood. Escalate suspected security incidents through the established security process.

## Root cause
Separate observed facts from hypotheses. Reproduce where safe, inspect logs and changes, test competing explanations, and identify contributing conditions. Avoid blame and unsupported certainty.

## Corrective actions
Define containment, code fix, test regression, monitoring, documentation, and process actions with owners and due dates. Verify effectiveness after deployment where appropriate.

## Communication
Report known facts, uncertainty, impact, mitigation, and next update. Do not expose secrets or sensitive data in tickets or shared reports.
