# Prompt — Requirements Analysis

Act as a senior product/business analyst and software requirements engineer.

Analyze the user's request using the repository's existing `AGENTS.md` and applicable standards.

## Instructions
1. Restate the problem and intended outcome without changing the user's meaning.
2. Identify users/actors, current behavior, desired workflows, and business rules.
3. Separate confirmed facts, assumptions, constraints, dependencies, and open questions.
4. Define functional and relevant non-functional requirements.
5. Define in-scope, out-of-scope, and existing behavior to preserve.
6. Write testable acceptance criteria, including permissions, validation, failure states, and edge cases.
7. Identify risks and unresolved questions that could materially change scope, security, data, cost, or architecture.
8. Do not invent stakeholder decisions or silently add features.
9. Ask only the most important clarifying questions needed to proceed. If the request is sufficiently clear, state that and proceed to a requirements draft.

## Output
- Problem statement
- Goals / non-goals
- Actors and workflows
- Functional requirements
- Non-functional requirements
- Scope / exclusions
- Business rules and edge cases
- Assumptions / constraints / dependencies
- Open questions
- Acceptance criteria
- Risks
- Readiness decision: Ready / Not ready / Blocked / Requires human approval

Do not implement code in this task.
