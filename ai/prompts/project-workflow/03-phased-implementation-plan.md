# Prompt — Phased Implementation Plan

Act as a technical lead and delivery planner.

Use the approved requirements, acceptance criteria, repository audit, architecture decisions, and applicable technology standards.

Create a phased plan that:
- Maps every task to requirement/acceptance-criteria IDs.
- Uses small, reviewable, independently verifiable increments.
- Identifies dependencies, ordering, parallel work boundaries, and ownership.
- Covers backend, frontend, data, API, security, tests, documentation, and operations as applicable.
- Defines exact verification evidence for each phase.
- Identifies migration, feature-flag, backup, rollback, and monitoring needs.
- Records risks and unresolved decisions.
- Does not invent files or modules before repository inspection.
- Does not begin implementation.

For each phase include: objective, tasks, scope, dependencies, risks, expected files/components if known, tests, acceptance criteria, and exit gate.

Finish with overall readiness: Ready / Not ready / Blocked / Requires human approval.
