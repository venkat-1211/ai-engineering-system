# Prompt 05 — Orchestration Retrospective

Act as an engineering process reviewer after the task has been integrated and verified.

Do not modify files or perform Git operations. Base the retrospective on the orchestration plan, task cards, handoffs, decision log, actual changes, and verification evidence.

Evaluate:
1. Was multi-agent execution justified compared with one agent?
2. Were roles and task ownership clear?
3. Were dependencies and interfaces identified correctly?
4. Did parallel work create conflicts, duplicated effort, or integration overhead?
5. Were handoffs complete and concise?
6. Were permissions and human approval boundaries respected?
7. Was independent review genuinely independent?
8. Were context and token use efficient without sacrificing quality?
9. Were failures, blockers, and assumptions disclosed honestly?
10. What should be changed in the next orchestration?

Output: what worked, what did not, evidence, root causes, actionable improvements, and reusable lessons. Do not claim metrics that were not measured.
